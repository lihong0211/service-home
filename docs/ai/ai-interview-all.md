# LLM、VLM、RAG 与 Agent 面试题完整版

> 面向大模型算法工程师、AI 应用工程师、Agent 工程师、RAG 工程师与模型评测岗位。  
> 本文将基础原理题与真实工程追问合并。稳定知识题给出参考答案；项目题给出答题框架。  
> 技术演进较快，具体模型版本、框架能力和榜单结果应在面试前结合最新资料更新。

## 使用方法

1. 先用 1～3 分钟口述答案，再查看参考答案。
2. 原理题按“结论—机制—优缺点—场景”回答。
3. 项目题按“背景—目标—方案—指标—问题—复盘”回答。
4. 不要编造项目数据。延迟、吞吐、成本、数据量等必须能解释统计口径。

## 一、LLM 基础原理与架构

### 1. Transformer 的自注意力如何工作？为什么比 RNN 更适合长序列？

**参考答案：** 输入分别投影为 Query、Key、Value，使用  
`Attention(Q,K,V)=softmax(QKᵀ/√d_k)V` 计算每个位置对其他位置的加权聚合。缩放项避免维度增大导致点积过大、Softmax 饱和。Transformer 能并行处理全部位置，任意两个 Token 的信息路径长度为 1；RNN 必须顺序计算，长距离信息需要经过很多状态传递。不过标准注意力的时间和显存复杂度是 `O(n²)`，长序列成本很高。

### 2. 为什么 Transformer 需要位置编码？有哪些实现？

**参考答案：** 自注意力本身对输入排列近似置换不变，因此必须注入顺序。常见方法包括正弦/余弦绝对位置编码、可学习绝对位置向量、RoPE 旋转位置编码、ALiBi 线性注意力偏置和相对位置编码。选型需要考虑长度外推、训练稳定性与推理实现。

### 3. RoPE 的原理是什么？相比绝对位置编码有什么特点？

**参考答案：** RoPE 将 Query、Key 的二维子空间按位置旋转，使点积自然包含相对位置信息。优点是无需额外位置向量、相对位置表达自然，并能配合缩放策略扩展上下文；缺点是超出训练长度时可能退化，高频维度旋转过快，需要 NTK-aware scaling、YaRN 等外推方法。RoPE 不等于天然支持无限上下文。

### 4. MHA、MQA 和 GQA 有什么区别？

**参考答案：** MHA 每个注意力头拥有独立的 Q/K/V；MQA 多个 Query 头共享一组 K/V；GQA 将 Query 头分组，每组共享 K/V。MQA 的 KV Cache 最小、推理快，但表达能力可能下降；GQA 在质量与推理效率之间折中，已成为许多生成模型的常见选择。

### 5. Encoder-only、Decoder-only 和 Encoder-Decoder 分别适合什么任务？

**参考答案：** Encoder-only 使用双向注意力，擅长分类、检索和表示学习；Decoder-only 使用因果注意力，擅长自回归生成和统一任务建模；Encoder-Decoder 由编码器理解输入、解码器生成输出，适合翻译、摘要等条件生成。当前通用 LLM 多采用 Decoder-only，原因包括统一训练目标和良好的扩展性，而不是它在所有任务上都必然最优。

### 6. Pre-Norm 和 Post-Norm 有什么区别？

**参考答案：** Post-Norm 在残差相加后归一化，原始 Transformer 使用该结构；Pre-Norm 在子层前归一化，使残差路径更直接，深层训练通常更稳定。Post-Norm 可能有更强表示，但需要更谨慎的初始化和学习率策略。现代 LLM 常用 Pre-Norm 或其变体。

### 7. LayerNorm 与 RMSNorm 有什么区别？

**参考答案：** LayerNorm 同时减均值并除以标准差；RMSNorm 只按均方根缩放，不做中心化，因此计算更简单。RMSNorm 在许多 LLM 中能保持相近效果并降低少量开销。两者都通常沿隐藏维进行，而 BatchNorm 依赖批统计，不适合变长序列和自回归推理。

### 8. LLM 常用哪些激活函数？为什么常见 SwiGLU？

**参考答案：** 常见激活包括 GELU、SiLU/Swish，以及门控结构 GLU、SwiGLU、GeGLU。SwiGLU 用一个分支产生门控、另一个分支承载值，通常比普通 ReLU/GELU FFN 具有更强表达力，但会增加投影参数，因此实现中常调整中间层宽度以控制总参数量。

### 9. BPE、WordPiece 和 SentencePiece 有什么区别？

**参考答案：** BPE 反复合并高频符号对；WordPiece 通常依据语言模型似然或类似准则选择子词；SentencePiece 是直接在原始 Unicode 文本上训练分词模型的工具框架，可实现 BPE 或 Unigram。评价 Tokenizer 不能只看词表大小，还要看压缩率、多语言公平性、数字和代码切分、未知字符及特殊 Token 处理。

### 10. 为什么 Decoder-only LLM 使用因果掩码？

**参考答案：** 因果掩码阻止当前位置看到未来 Token，使训练目标与逐 Token 生成一致。训练时虽然所有位置并行计算，但每个位置只预测下一个 Token；推理时逐步生成并复用 KV Cache。如果取消掩码，训练会发生未来信息泄漏。

### 11. Scaling Laws 说明了什么？

**参考答案：** 在一定范围内，模型损失与参数量、数据量和计算量呈近似幂律关系。核心意义是：固定计算预算下应协调模型规模和训练 Token，而不是只堆参数。Scaling Law 是经验规律，会受数据质量、架构、训练配方和任务分布影响，不能机械外推。

### 12. 如何理解“涌现能力”？

**参考答案：** 涌现通常指某些能力在规模增大后看似突然出现。但“突然”可能来自离散评价指标、提示方式或统计分辨率；换用连续指标后，部分能力呈平滑增长。因此不应声称存在统一的参数阈值，应区分真实能力变化与测量效应。

### 13. MoE 如何扩大参数量而不同比例增加计算？

**参考答案：** MoE 用路由器为每个 Token 选择少数专家，例如 Top-1 或 Top-2，因此总参数量很大，但单 Token 只激活部分参数。挑战包括负载不均衡、专家容量溢出、跨设备 All-to-All 通信、路由稳定性与推理部署复杂度。辅助负载均衡损失可缓解专家坍缩。

### 14. 什么是长上下文中的 Lost in the Middle？

**参考答案：** 模型对上下文开头和结尾的信息利用往往优于中间信息，即使相关证据已放入上下文也可能忽略。可通过检索和重排、把关键证据靠近问题、分段总结、减少噪声、层次化读取及专门的长上下文训练缓解。扩大窗口不等于能有效使用全部内容。

### 15. L1 与 L2 正则化有什么区别？

**参考答案：** L1 惩罚参数绝对值，倾向产生稀疏权重；L2 惩罚平方值，使权重整体缩小。深度学习常使用 Weight Decay；在 Adam 中，AdamW 将权重衰减与梯度更新解耦，比直接把 L2 项加入损失更符合预期。

## 二、训练、数据与微调

### 16. 预训练、SFT 和持续预训练有什么区别？

**参考答案：** 预训练在大规模通用语料上学习下一个 Token；持续预训练在领域无标注语料上继续同一目标以增强领域知识；SFT 使用输入—回答样本学习指令遵循。领域事实更新常优先考虑 RAG，行为格式和任务模式更适合 SFT，领域语言分布变化明显时可考虑持续预训练。

### 17. 训练百亿以上模型的主要挑战有哪些？

**参考答案：** 包括显存不足、计算量巨大、跨机通信、数据吞吐、数值不稳定、硬件故障和断点恢复。工程上采用数据/张量/流水线/序列并行、ZeRO/FSDP、混合精度、激活重计算、高效数据管线与容错检查点；算法上关注初始化、学习率、梯度裁剪、损失尖峰及数据质量。

### 18. FP16、BF16 和 FP32 的取舍是什么？

**参考答案：** FP32 精度和动态范围高但成本大；FP16 精度较低且指数范围小，训练常需 Loss Scaling；BF16 保留与 FP32 相同的指数位，动态范围更大，通常更适合大模型训练，但尾数精度较低。实际还会保留 FP32 主权重或优化器状态。

### 19. 什么是梯度累积和激活重计算？

**参考答案：** 梯度累积把多个小 Micro-batch 的梯度累加后再更新，模拟更大 Batch，但不会减少总计算；激活重计算在反向传播时重新计算部分前向激活，以计算换显存。两者都可能降低吞吐，需要结合通信和显存瓶颈评估。

### 20. LoRA 的原理是什么？rank 如何选择？

**参考答案：** LoRA 冻结原权重，用低秩矩阵 `ΔW=BA` 学习权重增量，从而减少可训练参数和优化器显存。rank 越大容量越强但成本越高；应通过验证集和消融实验选择，同时关注目标模块、缩放系数、学习率和数据规模。不是 rank 越大越好。

### 21. QLoRA 为什么能降低微调显存？

**参考答案：** QLoRA 将基础模型以低比特格式存储并冻结，仅训练 LoRA 参数，计算时按需反量化。其关键思想包括 4-bit NormalFloat、双重量化和分页优化器。它降低显存但不代表训练计算完全按 4-bit 进行，也可能带来吞吐和量化误差问题。

### 22. 多轮对话 SFT 中哪些 Token 应计算 Loss？

**参考答案：** 通常只对 Assistant 输出 Token 计算损失，用户、系统提示和工具结果作为条件但掩蔽 Loss。也可根据目标训练工具调用或推理轨迹。若模板边界、特殊 Token 或掩码错误，模型可能学会复述用户、破坏角色边界或无法正确停止。

### 23. 如何构建高质量 SFT 数据？

**答题框架：** 说明数据来源、许可与隐私；执行去重、语言和长度过滤、毒性/PII 检查、格式校验；建立质量评分和人工抽检；按任务与难度分层；防止训练测试泄漏；记录数据版本。最后通过固定评测集和消融实验验证每类数据的边际收益。

### 24. 训练 Loss 降低但业务效果不提升，为什么？

**参考答案：** 可能是训练目标与业务指标不一致、数据过易或泄漏、验证分布失真、过拟合格式、评测噪声、生成参数不一致，或模型只提升了高频模式。应按任务切片检查，比较基线与消融，人工分析 Bad Case，并确认训练和线上 Prompt 模板一致。

### 25. 如何处理灾难性遗忘？

**参考答案：** 可混入通用数据、降低学习率和训练步数、使用参数高效微调、正则化或多任务训练，并持续进行通用能力回归测试。首先要区分真正的遗忘、提示模板变化和评测波动。

### 26. 合成数据有什么价值与风险？

**参考答案：** 合成数据可扩展稀缺任务、覆盖边界情况并控制格式，但会继承教师模型偏见与错误，产生模式单一和“模型坍缩”。应使用多来源教师、规则/执行器验证、去重、难度筛选、人工抽检，并保留真实数据作为锚点。

### 27. 如何避免训练集与评测集泄漏？

**参考答案：** 做文档级与样本级精确去重、MinHash/向量近重复检测、时间切分、来源隔离和题目变体检测。代码与数学题还要检查答案和解题轨迹泄漏。仅按字符串完全匹配不足以发现改写后的污染。

### 28. 如何设计 Tool Calling 的训练数据？

**答题框架：** 覆盖正确选工具、无需调用、缺参追问、参数约束、工具错误、重试与终止；同时加入相似工具的困难负样本。轨迹应校验 Schema、业务约束和最终状态，避免把错误工具结果当作正确监督。

## 三、对齐、RLHF 与偏好优化

### 29. 为什么 SFT 后还需要偏好对齐？

**参考答案：** SFT 主要模仿示范答案，不能充分表达多个可接受回答之间的偏好，也难直接优化帮助性、安全性和风格。偏好对齐使用比较信号塑造输出分布。但对齐无法凭空增加知识，偏好数据偏差还可能造成奉承、冗长和模式化。

### 30. 经典 RLHF 的三个阶段是什么？

**参考答案：** 第一阶段用高质量示范进行 SFT；第二阶段收集成对偏好并训练奖励模型；第三阶段以奖励为目标，通过 PPO 等算法更新策略，同时用 KL 约束避免偏离参考模型。实际系统还包含数据迭代、安全评测和在线反馈闭环。

### 31. 为什么奖励模型常用成对比较数据？

**参考答案：** 人类更容易稳定判断 A 比 B 好，而不是给出跨样本一致的绝对分数。常用 Bradley–Terry 假设 `P(A>B)=σ(r_A-r_B)` 并优化对数似然。缺点是标注成本仍高、无法表达平局和多维偏好，并可能存在位置、长度和标注者偏差。

### 32. 为什么 PPO 中要加入 KL 约束？

**参考答案：** KL 约束限制新策略偏离参考模型，防止为了奖励模型漏洞而牺牲语言质量和多样性。系数过大会导致几乎学不到偏好；过小会造成策略漂移和 Reward Hacking。通常监控 KL、奖励、长度、熵和人工质量，并动态调节系数。

### 33. DPO 的核心思想是什么？

**参考答案：** DPO 将 KL 约束下的最优策略与奖励函数关系代入偏好模型，直接用 chosen/rejected 对训练策略，无需显式奖励模型和在线 PPO Rollout。它更简单稳定，但仍依赖偏好数据质量和参考模型，对探索、可验证在线奖励及复杂信用分配未必优于 RL。

### 34. PPO、GRPO 的主要区别是什么？

**参考答案：** PPO 通常训练价值模型估计 Advantage；GRPO 对同一问题采样一组回答，用组内奖励相对标准化估计 Advantage，从而省去独立 Critic。GRPO 适合可批量采样、奖励可验证的任务，但对组大小、奖励方差和采样成本敏感。

### 35. 如何理解 DAPO、GSPO 等后续方法？

**参考答案：** 它们主要围绕组式策略优化的稳定性、裁剪粒度、采样效率、长度偏差和 Token/序列级目标进行改进。面试不要只背缩写，应说清论文要解决的问题、目标函数与 GRPO/PPO 的关键差异，并以最新论文版本为准。

### 36. 什么是 Reward Hacking？

**参考答案：** 策略找到奖励模型或规则的漏洞，获得高分但不满足真实目标。例如 Judge 偏好长答案，模型便生成冗长空话。缓解方式包括多维奖励、对抗样本、规则与执行器校验、奖励模型集成、KL 约束、人工抽检和线上监控。

### 37. Token 级奖励和序列级奖励有什么区别？

**参考答案：** 序列级奖励只评价最终输出，简单但信用分配困难；Token/步骤级奖励提供密集监督，更利于长链推理，却需要可靠的过程标注或验证器，错误过程奖励可能把模型引向局部最优。实践中可结合最终可验证奖励与过程奖励。

### 38. 什么是 RLAIF？风险是什么？

**参考答案：** RLAIF 使用 AI 生成偏好、批评或原则反馈，降低人工标注成本并扩大覆盖。风险包括教师偏见放大、循环自强化、对抗样本漏检和“同源模型偏爱同类答案”。需要人工锚点、多模型交叉评审和外部可验证信号。

### 39. 对齐后模型变得奉承、模式化，如何排查？

**答题框架：** 检查偏好数据是否偏爱肯定用户、长答案或固定格式；检查奖励模型偏差、KL、采样温度和拒答模板；按任务切片比较 SFT 与对齐模型；引入反奉承、简洁性和纠错样本，使用多目标评估而非只看奖励分数。

## 四、推理优化与部署

### 40. Prefill 与 Decode 阶段有什么区别？

**参考答案：** Prefill 并行处理全部输入 Token，矩阵计算规模大，通常更偏计算密集；Decode 每步只生成一个 Token，但反复读取模型权重和 KV Cache，常更偏显存带宽受限。TTFT 主要受 Prefill 和排队影响，TPOT 主要受 Decode、批处理和带宽影响。

### 41. KV Cache 的作用和代价是什么？

**参考答案：** 自回归生成时缓存各层历史 Token 的 K/V，避免每一步重新计算历史。显存大致与层数、序列长度、KV 头数、头维度、批量和数据类型成正比。GQA/MQA、低精度 KV、分页管理和前缀缓存可降低成本。

### 42. vLLM 的 PagedAttention 解决什么问题？

**参考答案：** 它借鉴虚拟内存分页，把逻辑连续的 KV Cache 映射到非连续物理块，减少预留和碎片浪费，并支持共享前缀与更灵活的批调度。它优化的是 KV 内存管理，不会消除注意力计算本身。

### 43. Continuous Batching 为什么能提高吞吐？

**参考答案：** 不等待整个静态 Batch 完成，而是在每个调度步移除已结束请求、加入新请求，提高 GPU 利用率。代价是调度复杂、单请求延迟可能波动，需要在吞吐、TTFT、TPOT 和公平性之间权衡。

### 44. Tensor、Pipeline、Data Parallel 如何选？

**参考答案：** Data Parallel 复制模型、切分数据，适合模型能放入单设备；Tensor Parallel 在层内切矩阵，低延迟但通信频繁；Pipeline Parallel 按层切阶段，适合超大模型但有流水线气泡。大规模部署通常组合使用，并结合网络拓扑选择。

### 45. GPTQ、AWQ 和运行时量化有什么区别？

**参考答案：** GPTQ 是基于校准数据的训练后权重量化，近似最小化重构误差；AWQ 保护对激活重要的权重通道；运行时量化还可能量化激活和 KV Cache。评估不能只看困惑度，应覆盖目标任务、长文本、工具调用、速度、显存和实际硬件算子。

### 46. Speculative Decoding 为什么能加速？

**参考答案：** 小草稿模型快速生成多个候选 Token，大模型一次并行验证，在保持目标分布的情况下接受多个 Token。收益取决于接受率、草稿模型速度、序列长度和系统开销；若模型差异大或批量很高，收益可能很小。

### 47. 如何理解 TTFT、TPOT、吞吐和端到端延迟？

**参考答案：** TTFT 是首 Token 时间，影响交互响应；TPOT 是后续 Token 间隔，影响流式速度；吞吐可按请求或 Token/秒衡量；端到端延迟还受输出长度影响。优化一个指标可能伤害另一个，例如扩大 Batch 提升吞吐却增加排队和 TTFT。

### 48. 模型服务出现 OOM，如何排查？

**答题框架：** 先区分权重、KV Cache、激活、临时算子和内存碎片；记录并发、输入/输出长度和批大小；复现触发边界；再考虑降低最大 Token/并发、采用 GQA/量化、Paged KV、分片或请求限流。不能只靠重启。

### 49. 平均延迟正常但 P99 很高，如何定位？

**答题框架：** 分解排队、Tokenizer、Prefill、Decode、网络和下游工具时间；按输入长度、输出长度、模型、租户和时间段切片；检查动态批处理中的长请求阻塞、冷启动、GC、重试和资源争用；使用 Trace 而非只看平均值。

### 50. GPU 利用率只有 30%，可能是什么原因？

**参考答案：** 可能是请求不足、Batch 太小、CPU/Tokenizer/数据加载瓶颈、网络通信等待、频繁同步、小算子过多、Decode 带宽受限或负载不均衡。需要同时查看 SM 利用率、显存带宽、Kernel 时间、队列深度和主机侧 Profiling。

### 51. 如何设计模型服务的超时、重试和降级？

**参考答案：** 设置端到端 Deadline，并把预算传递给下游；只对幂等、瞬时错误做有限指数退避重试，避免重试风暴；用限流、熔断和隔离保护系统；降级可切小模型、缩短上下文、关闭非关键工具或返回可解释错误。

### 52. 如何进行模型路由？

**答题框架：** 根据任务难度、模态、上下文长度、SLA、成本和安全级别选择模型；先用规则或轻量分类器，再结合在线反馈更新。必须监控路由错误、质量、延迟与成本，并准备供应商故障回退。

## 五、VLM 与多模态

### 53. VLM 的核心挑战是什么？

**参考答案：** 关键包括视觉和语言表征对齐、不同分辨率和 Token 数量、细粒度 Grounding、时序理解、视觉幻觉、数据质量以及多模态推理成本。仅把视觉向量投影到 LLM 并不保证模型真正利用图像。

### 54. CLIP 如何连接图像和文本？

**参考答案：** CLIP 使用图像编码器和文本编码器，将配对图文映射到同一向量空间，通过批内对比学习提高匹配对相似度、降低非匹配对相似度。它擅长零样本分类和检索，但对细粒度空间关系、计数和 OCR 可能不足。

### 55. LLaVA 类模型如何连接视觉编码器与 LLM？

**参考答案：** 通常使用预训练视觉编码器提取 Patch 特征，经线性层或 MLP Projector 映射到 LLM 嵌入空间，再作为视觉 Token 输入。训练常分为特征对齐和视觉指令微调。更复杂结构可使用 Q-Former、Cross-Attention 或动态视觉 Token。

### 56. 什么是视觉指令微调？

**参考答案：** 使用图像—指令—回答数据训练模型遵循多模态任务要求，使其从“图文对齐”转为可对话、可推理的助手。数据应覆盖描述、VQA、OCR、Grounding、拒答和困难负样本，并防止语言模板压过真实视觉证据。

### 57. 如何处理高分辨率图片？

**参考答案：** 可直接缩放、切 Tile、动态分辨率或使用多尺度特征。缩放成本低但会丢小字；切块保留细节但增加视觉 Token，且需要维护全局布局与块间关系。应按任务对清晰度、延迟和 Token 预算做权衡。

### 58. VLM 的视觉幻觉与文本幻觉有何不同？

**参考答案：** 视觉幻觉表现为捏造不存在的物体、属性、数量、文字或空间关系。原因可能是视觉信息不足、图像压缩、语言先验过强或训练数据偏差。可用 Grounding、OCR/检测器校验、反事实图像测试和“看不清则拒答”数据缓解。

### 59. 什么是 Grounding？如何评估？

**参考答案：** Grounding 是把语言中的实体或描述定位到图像区域。常用边界框 IoU、指向准确率、区域召回和短语定位指标；对于开放式输出，还要解析坐标格式并检查实体—区域对应关系。

### 60. 视频相比图片额外有哪些问题？

**参考答案：** 视频需要处理时间顺序、动作和事件边界、长时依赖、重复帧以及音视频同步。均匀采样可能错过短暂事件，可结合镜头切分、运动强度、关键帧检索和层次化时序建模。

### 61. OCR 与 VLM 应该如何组合？

**参考答案：** OCR 适合精确文字识别和坐标，VLM 擅长语义、版面和跨区域推理。生产系统常先 OCR，再把文字、坐标和图片证据提供给 VLM；对关键字段使用规则或校验器验证，不能无条件相信任一方。

### 62. 如何评估文档 VLM？

**参考答案：** 按 OCR、版面、表格、图表、跨页引用、键值抽取和问答分层评估；既看最终答案，也看区域证据和字段级准确率。测试集应覆盖扫描噪声、旋转、小字、多栏、合并单元格及不同语言。

## 六、RAG 与搜索系统

### 63. RAG 的完整流程是什么？与微调如何取舍？

**参考答案：** 流程包括采集、解析、清洗、切块、Embedding、建索引、查询理解、召回、重排、上下文构造、生成和引用。RAG 适合动态知识、可追溯回答和权限过滤；微调更适合行为、格式和固定能力。两者可以组合。

### 64. 如何选择切块大小和重叠？

**参考答案：** 应由文档结构、问题粒度、Embedding 模型和上下文预算决定。块太小缺上下文，太大引入噪声并降低检索区分度。优先按标题、段落、表格等语义边界切分，再用评测集搜索参数；重叠用于保留边界信息，但会增加索引和重复召回。

### 65. 如何选择 Embedding 模型？

**参考答案：** 关注目标语言和领域、查询—文档长度、是否支持非对称检索、维度、吞吐、许可证和部署成本。用业务查询评估 Recall@K、MRR、nDCG，并按问题类型切片。公开榜单只能作为初筛。

### 66. 为什么生产 RAG 常用混合检索？

**参考答案：** Dense Retrieval 擅长语义相似，BM25 擅长精确关键词、编号、专有名词和稀有词。混合检索可用加权分数或 RRF 融合，再用 Cross-Encoder Reranker 精排，提高鲁棒性。

### 67. Reranker 的作用是什么？

**参考答案：** 初召回需要高召回率，Reranker 对 Query—Chunk 对做更精细的相关性判断，提高 Top-N 精度。候选太少会漏证据，太多增加延迟；应通过 Recall@K、最终准确率和 P95 延迟共同选择。

### 68. 用户问到了库中内容但没有召回，如何排查？

**答题框架：** 沿数据链路排查：原文是否入库、解析是否丢失、切块是否破坏语义、元数据权限是否过滤、Embedding 是否一致、查询是否需改写、ANN 参数是否过严、重排是否误杀。保存每阶段候选和分数，避免只看最终答案。

### 69. 如何处理表格、图片和跨页 PDF？

**参考答案：** 使用保留版面的解析器，表格以 Markdown/HTML 或结构化行列保存，并保留页码、标题和坐标；图片可做 OCR/VLM 描述并链接原区域；跨页章节按文档结构合并。关键是让检索单元可搜索且可回溯原始证据。

### 70. 如何实现多租户与文档级权限？

**参考答案：** 在索引中存租户、文档和 ACL 元数据，并在召回阶段强制过滤；授权必须在服务端执行，不能靠 Prompt。缓存键、日志、向量索引和对象存储都要隔离，且权限变更后及时失效。

### 71. 文档更新和删除后如何保持索引一致？

**参考答案：** 使用稳定文档 ID、内容哈希和版本号，按事件增量更新；写入采用幂等 Upsert，删除使用 Tombstone 或明确删除；建立源数据与索引对账、失败重试和重建机制。缓存也要随版本失效。

### 72. 如何生成可靠引用？

**参考答案：** 为每个 Chunk 保留来源、页码和位置；生成时要求答案声明所用证据，并在后处理验证引用是否真实支持对应陈述。若证据不足应明确说明，而不是引用相关但不支持结论的段落。

### 73. 检索结果互相冲突怎么办？

**参考答案：** 比较来源权威性、时间、版本和适用范围；将冲突证据同时提供给模型，要求明确指出差异。关键业务可制定来源优先级或转人工。不能让模型静默挑选最符合语言先验的一条。

### 74. 如何构建 RAG 评测集？

**答题框架：** 从真实日志、专家设计和文档生成候选问题；标注答案、支持证据、不可回答问题和问题类别；去重并防泄漏；分别评估解析、召回、重排、Faithfulness、答案正确性和引用质量；持续把线上 Bad Case 回流。

### 75. RAG 与搜索系统有什么区别？

**参考答案：** 搜索主要返回排序后的文档或结果，优化相关性、覆盖和点击；RAG 在检索后生成综合答案，还需评估事实一致性、引用和生成风险。RAG 的检索底座往往就是搜索系统，但生成层引入了额外不可控性。

### 76. 什么是 Agentic RAG？

**参考答案：** Agent 根据问题决定是否检索、如何拆解查询、调用哪些数据源，并可多轮检索和验证。它适合复杂问题，但增加延迟、成本和失败路径。应设置步骤预算、停止条件、工具权限与轨迹评估。

### 77. 如何防御知识库中的 Prompt Injection？

**参考答案：** 把检索内容视为不可信数据，明确区分指令与证据；过滤可疑指令；工具授权由代码控制；敏感操作要求确认；限制数据外传；记录来源并进行输出检查。仅在 System Prompt 写“忽略恶意内容”不够。

## 七、Agent、工具调用与多智能体

### 78. 什么是 LLM Agent？核心组件有哪些？

**参考答案：** Agent 是让模型围绕目标感知状态、规划、调用工具并根据结果继续决策的系统。核心包括模型、指令、工具、状态/记忆、规划或工作流、执行器、权限、安全策略、观测和评估。

### 79. ReAct 的核心思想是什么？

**参考答案：** ReAct 交替进行 Reasoning 与 Action：模型根据当前观察选择动作，环境返回 Observation，再继续推理。优点是能利用外部信息并暴露轨迹；缺点是步骤多、成本高，容易循环或被恶意观察污染。

### 80. CoT、ToT、GoT 等规划方法如何理解？

**参考答案：** CoT 生成线性中间推理；ToT 搜索多个思路分支并评估；GoT 允许更一般的图结构组合。更复杂搜索不一定更好，只有当任务可分解、候选可评价且收益覆盖额外成本时才值得使用。

### 81. Function Calling 是如何工作的？

**参考答案：** 应用向模型提供工具名称、描述和参数 Schema；模型输出结构化工具选择和参数；应用校验、授权并执行，再把结果返回模型。模型只提出调用建议，真正的权限、校验、幂等和审计必须由应用负责。

### 82. JSON 合法但业务参数错误怎么办？

**参考答案：** Schema 只能保证结构。还要做类型范围、枚举、跨字段约束、资源存在性、权限和业务状态校验。错误应以结构化、最小必要信息返回模型；高风险参数需人工确认。

### 83. 如何防止 Agent 工具调用死循环？

**参考答案：** 设置最大步数、时间、Token 和费用预算；记录动作签名并检测重复；要求每步状态有进展；对连续相同错误采用熔断；必要时转人工或返回部分结果。只依赖模型自行停止不可靠。

### 84. 工具失败后什么时候重试？

**参考答案：** 网络抖动、限流等瞬时错误且操作幂等时可有限重试；参数错误、权限错误和永久业务错误不应盲目重试。对非幂等写操作需使用幂等键、查询执行状态或补偿事务。

### 85. 如何处理 Agent 已产生副作用但后续失败？

**参考答案：** 采用 Saga/补偿动作记录每一步状态；可回滚操作执行逆操作，不可回滚操作进入人工处理；把任务设计为可恢复状态机并持久化事件。模型不能自行假设外部操作已撤销。

### 86. 哪些工具调用必须人工确认？

**参考答案：** 转账、下单、删除、发布、发送外部消息、权限变更和敏感数据访问等高影响动作。确认页面应展示最终工具、目标、关键参数和影响，确认后若参数变化必须重新确认。

### 87. Agent 记忆如何设计？

**参考答案：** 短期记忆保存当前任务状态和最近交互；长期记忆保存稳定偏好、事实或历史摘要。应区分原始记录、摘要和结构化状态，设置来源、置信度、过期、用户可查看/删除机制，避免错误记忆永久污染。

### 88. 为什么生产 Agent 常像状态机？

**参考答案：** 状态机为步骤、允许动作、错误恢复和审计提供明确边界；模型只在需要语义判断的节点决策。完全自治 ReAct 灵活但路径不可预测。高风险、强流程业务通常采用确定性工作流加局部 LLM 决策。

### 89. 单 Agent、工作流与多 Agent 如何选？

**参考答案：** 路径固定时用工作流；任务开放但工具有限时用单 Agent；只有角色确实需要不同上下文、工具或并行能力时才用多 Agent。多 Agent 会增加通信、重复工作、冲突、延迟和评估复杂度。

### 90. 多 Agent 如何避免重复工作和互相等待？

**参考答案：** 明确角色、输入输出契约和任务所有者；共享结构化任务板而非无限对话；使用超时、依赖图、去重键和仲裁者；限制上下文传播。评估应比较其相对单 Agent 的净收益。

### 91. MCP 解决了什么问题？

**参考答案：** MCP 为模型应用连接工具、资源和提示提供标准化协议，降低每个客户端与数据源单独集成的成本。它不自动解决工具质量、权限、安全、事务、Prompt Injection 或 Agent 可靠性。

### 92. 如何持久化并恢复 Agent 任务？

**参考答案：** 将状态、已执行动作、工具结果、预算和待确认项写入持久存储；每一步使用幂等标识；恢复时从最后一个已提交状态继续，而不是重放所有副作用。事件日志有助于审计和重放。

### 93. 如何调试失败的 Agent？

**答题框架：** 记录模型版本、Prompt、工具 Schema、每步输入输出、延迟、Token、费用、错误、状态变更和最终结果；用统一 Trace ID 串联。先判断是规划、工具选择、参数、工具执行、观察理解还是停止条件失败，再建立对应回归用例。

### 94. LangChain 与 LlamaIndex 如何选？

**参考答案：** 两者能力边界不断变化。一般来说，LangChain/LangGraph 更强调模型应用编排和有状态工作流，LlamaIndex 强调数据接入、索引和检索抽象。选型应基于项目版本、可观测性、可测试性、依赖复杂度和团队维护能力，避免只比较功能清单。

## 八、模型、RAG 与 Agent 评估

### 95. 为什么 BLEU、ROUGE 不足以评估现代 LLM？

**参考答案：** 它们主要度量与参考答案的词面重合，对开放生成中的同义表达、事实性、推理和帮助性不敏感。可将确定性任务指标、语义指标、可执行验证、LLM Judge 和人工评估组合使用。

### 96. 常见 LLM Benchmark 分别测什么？

**参考答案：** MMLU 类测试多学科知识，GSM/数学集测试数学推理，HumanEval 类用单元测试评估代码，TruthfulQA 关注误导性事实，安全集测试越狱和有害输出。榜单分数受 Prompt、采样、污染和评测脚本影响，不能替代业务评测。

### 97. LLM-as-a-Judge 有哪些偏差？

**参考答案：** 常见位置偏差、长度偏差、风格偏差、自家族偏差和对权威措辞的偏好。可交换候选顺序、多次评审、隐藏模型身份、使用明确 Rubric、提供证据、用人工样本校准并报告一致性。

### 98. 如何评估幻觉和事实性？

**参考答案：** 把回答拆成可验证陈述，检查是否被来源支持；对有标准答案任务计算事实准确率；RAG 同时评估 Context Relevance、Faithfulness 和 Answer Correctness。还应覆盖不可回答问题，检查模型是否合理拒答。

### 99. 为什么 Agent 评估更困难？

**参考答案：** Agent 输出不仅是文本，还包含多步决策、环境状态和副作用；同一任务可能有多条正确路径，环境也可能不稳定。需同时评估任务成功、步骤正确性、工具错误、成本、延迟、安全、恢复能力和重复运行方差。

### 100. Agent 应关注哪些过程指标？

**参考答案：** 工具选择准确率、参数正确率、无效调用数、步骤数、重试率、循环率、Token/费用、延迟、人工介入率和安全违规率。最终成功但过程极其昂贵或危险，不能视为优质 Agent。

### 101. 如何建立 Golden Dataset？

**答题框架：** 从真实高价值流量和关键风险出发，定义任务分类与 Rubric；由领域专家标注答案、证据或最终状态；覆盖正常、长尾、对抗和不可回答案例；版本化并隔离测试；持续从线上 Bad Case 增量更新。

### 102. 如何做人工评估？

**参考答案：** 明确定义互斥、可操作的评分标准；培训标注员并提供正反例；随机化和匿名化候选；设置重复样本与金标；统计一致性，如 Cohen/Fleiss Kappa；对分歧仲裁并记录原因。

### 103. 如何评估非确定性输出？

**参考答案：** 固定核心配置并进行多次采样，报告均值、方差、Pass@k 或成功率置信区间。对 Agent 应重复运行相同任务，区分模型随机性和环境不稳定性。一次通过不足以证明可靠。

### 104. 如何做线上 A/B 测试？

**参考答案：** 预先定义主指标、护栏指标、样本量和停止规则；按用户稳定分桶，避免串组；同时观察质量、留存、延迟、成本和安全；检查新奇效应与分群差异。高风险能力先灰度或 Shadow Test。

### 105. 如何监控线上 LLM 应用？

**参考答案：** 监控请求量、错误率、TTFT、TPOT、Token、成本、模型/工具失败、拒答、用户反馈、任务成功和安全事件；按模型、版本、场景、租户切片；保存合规的可审计 Trace，并对漂移和回归设置告警。

### 106. 如何把线上 Bad Case 转为回归测试？

**参考答案：** 去除隐私并最小化复现输入，标注期望行为和失败类型，加入对应切片评测集；固定模型和 Prompt 版本，记录修复前后结果；避免只为单个样本写过拟合规则。

## 九、安全、隐私与生产治理

### 107. Prompt Injection 与 Jailbreak 有什么区别？

**参考答案：** Jailbreak 通常是用户直接诱导模型绕过安全策略；Prompt Injection 是不可信内容尝试覆盖系统指令，可能来自用户，也可能来自网页、邮件或 RAG 文档。间接注入更隐蔽，因为恶意指令藏在工具读取的数据中。

### 108. 为什么仅靠 System Prompt 不能保证安全？

**参考答案：** 模型不是形式化权限系统，可能受冲突指令、编码变体和上下文污染影响。安全应由代码层权限、Schema 校验、数据隔离、最小权限、人工确认、输出过滤和审计共同保证。

### 109. 如何实施工具最小权限？

**参考答案：** 每个工具只暴露必要操作和数据范围；读写分离；凭证短期化并绑定用户/租户；高风险操作单独授权；默认拒绝；服务端再次检查身份和资源权限。不要把万能管理员 API 直接交给模型。

### 110. 如何防止多租户数据泄漏？

**参考答案：** 在身份、数据库、向量索引、缓存、对象存储和日志各层实施租户隔离；所有查询强制带服务端租户条件；缓存键包含租户；测试越权访问；敏感 Trace 脱敏并设置保留期。

### 111. 如何处理 PII、密钥和内部数据？

**参考答案：** 数据进入模型前做分类与最小化，检测并脱敏 PII/密钥；使用符合要求的模型部署与数据协议；限制日志内容和保留时间；输出端再次检测；支持访问、删除和审计。真正的密钥不应放入 Prompt。

### 112. 如何审计高风险工具调用？

**参考答案：** 记录调用者、模型和 Prompt 版本、工具、参数摘要、授权依据、人工确认、执行结果、时间和关联 Trace。日志应防篡改且受访问控制，同时避免记录完整敏感内容。

### 113. 外部模型 API 故障如何降级？

**参考答案：** 设置 Deadline、限流、熔断和健康检查；按能力准备备用模型并做兼容性回归；可降级到小模型、缓存答案、只检索不生成或转人工。切换模型时注意 Prompt、工具调用和安全行为不完全兼容。

## 十、项目设计、线上排障与连续追问

### 114. 请画出你做过的 LLM/Agent 系统架构。

**答题框架：** 从入口、鉴权、编排、模型、检索、工具、状态、观测和数据闭环依次讲；说明同步/异步链路、部署方式和故障边界。最后指出自己负责的模块，不要把团队成果全部说成个人成果。

### 115. 为什么这个需求要用 LLM，而不是规则或搜索？

**答题框架：** 先明确任务是否需要开放语义理解、生成或复杂归纳；给出规则/搜索 Baseline；比较质量、覆盖、维护成本、延迟、费用和风险。若传统方法足够，应坦诚使用更简单方案。

### 116. 模型是如何选型的？

**答题框架：** 定义任务集和护栏；选择质量、延迟、成本、上下文、工具调用、安全与部署约束；统一 Prompt 和生成参数做盲测；按场景切片；最终说明为什么选中的模型在 Pareto 前沿，而不是只说榜单最高。

### 117. 项目中最难的问题是什么？

**答题框架：** 用 STAR：背景和约束、你的职责、诊断证据、候选方案、实验与结果、复盘。必须准备量化前后对比，并能解释指标口径和显著性。

### 118. 离线效果好、线上效果差，可能为什么？

**参考答案：** 测试集不代表真实分布、数据泄漏、线上 Prompt/参数不同、工具或检索不稳定、延迟导致用户流失、Judge 偏差、流量选择偏差或用户行为改变。应先验证链路一致性，再按线上流量切片回放。

### 119. 如何证明提升来自你的方案？

**参考答案：** 使用同一数据和固定其他变量的对照实验、消融实验或 A/B 测试；报告置信区间和分群结果；排除模型版本、数据更新和 Prompt 同时变化。若多个因素一起上线，就不能准确归因。

### 120. 流量扩大十倍，哪里最先出问题？

**答题框架：** 根据实际架构分析入口限流、模型队列、GPU KV Cache、向量库、下游 API、数据库连接、日志量和费用；给出容量模型、压测方法、自动扩缩容、背压与降级策略。

### 121. 项目最失败的一次方案是什么？

**答题框架：** 选择真实且有判断价值的失败；说明当时假设、验证证据、为何失败、如何止损和沉淀机制。重点是学习和工程判断，不要把无关小问题包装成“失败”。

### 122. 如果重新设计一次，你会改变什么？

**答题框架：** 从当时信息出发评价，而不是事后诸葛亮；指出架构边界、评测、数据、可观测性或安全方面的具体改变，并说明预期收益和迁移成本。

### 123. 如何回答项目的指标追问？

**参考答案：** 准备数据量、成功率、准确率、P50/P95/P99、吞吐、Token、单次成本和人工介入率；每个数字都说明时间范围、样本数、分母、是否线上、如何采集。不能透露的信息可给范围或比例，但不要编造。

### 124. 一套典型的连续压力追问是什么？

**参考答案：**

1. 你的准确率是多少？
2. 准确率如何定义？
3. 测试集从哪里来？
4. 样本量和类别分布如何？
5. 谁标注？一致性是多少？
6. 是否有数据泄漏？
7. Baseline 是什么？
8. 提升是否显著？
9. 最差类别是什么？
10. 为什么差？做过什么消融？
11. 线上是否保持？
12. 十倍流量如何扩容？

## 十一、趋势与开放题

### 125. 如何看待开源模型与闭源模型？

**答题框架：** 从能力、成本、可控性、隐私、迭代速度、生态和供应商锁定比较。闭源通常易用且前沿能力强，开源便于私有化和定制。实际常采用多模型路由，不必二选一。

### 126. Transformer 会长期占主导吗？

**答题框架：** Transformer 具备成熟生态和良好扩展性；SSM、线性注意力和混合架构在长序列效率上有潜力。评价新架构要同时看训练扩展、质量、硬件效率、推理生态和真实任务，而非只看理论复杂度。

### 127. 当前 Agent 最大瓶颈是什么？

**参考答案：** 通常是可靠性而非“不会调用工具”：长程规划不稳定、错误累积、环境不可控、评测困难、成本与延迟、安全和权限治理都限制落地。不同场景瓶颈不同，应结合任务成功率与商业价值回答。

### 128. 高质量合成数据未来会扮演什么角色？

**参考答案：** 它会用于覆盖长尾、过程监督、自博弈和可验证任务，但必须以真实数据、规则或环境反馈为锚点。核心竞争力将从“生成更多数据”转向“验证、筛选和组织更有效的数据”。

### 129. 个性化 Agent 如何平衡效果与隐私？

**参考答案：** 采用明确同意、数据最小化、分层记忆、可查看/编辑/删除、敏感属性限制、端侧处理或加密存储；个性化决策要可解释并能关闭。不能为了效果无限积累用户数据。

### 130. 顶尖 AI Agent 工程师需要哪些能力？

**参考答案：** 既理解模型边界，也具备软件工程、分布式系统、搜索/RAG、评估、数据、安全和产品判断；能把开放问题约束成可测系统，能用指标定位失败，并能在质量、成本、延迟与风险之间做取舍。
